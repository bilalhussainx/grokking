## Source-backed gaps requiring targeted verification

1. **High — Comment creation does not verify essay ownership.** `src/app/api/counselor/students/[studentId]/essays/[essayId]/route.ts:42` authorizes the path's student, but comment branch `:60`–`:83` passes arbitrary `essayId` to `src/lib/cc/counselor-comments.ts:170`, which inserts through an admin client without resolving essay ownership. `artifact_id` is unconstrained text (`supabase/migrations/20260515_counselor_workspace.sql:127`). A counselor with one valid roster student can supply a different student's known essay ID; the read helper selects comments by artifact ID (`src/lib/cc/counselor-comments.ts:127`–`:133`), so the foreign essay can receive injected feedback. This is a static control-flow finding, not an executed exploit.
2. **High — Draft comments are not agency-filtered on reads.** `src/lib/cc/counselor-comments.ts:127`–`:133` uses admin access and selects all essay comments without agency/student filters. Student links are unique by agency+student, so the schema permits multi-agency students (`supabase/migrations/20260515_counselor_workspace.sql:61`). If two agencies legitimately link the same student, one can read the other's draft comments through the counselor essay endpoint. Deployed constraints and runtime exploitability were not checked.
3. **Approval gate covers comments, not review decisions.** `src/app/api/counselor/students/[studentId]/essays/[essayId]/route.ts:86`–`:94` permits any visible counselor to mark approved/request changes, without checking `requiresReview`; UI buttons at `src/app/counselor/students/[studentId]/page.tsx:272`, `:280` are also unrestricted. If approval is required for all outward feedback, this is a bypass. If the rule intentionally covers only comment prose, document that distinction before auditing.
4. **Head cannot publish drafts through the inspected UI.** Comment status API exists, but `src/app/counselor/students/[studentId]/page.tsx:293`–`:314` only renders status labels/body, including “awaiting head approval”; no matching status endpoint caller found. Approving an essay does not ship its comments. A supervised counselor's prose can remain indefinitely hidden from the student.
5. **Review assignments do not reach a usable review queue.** Create helper stores `status: "assigned"` at `src/lib/cc/agency-assignments.ts:158`; dashboard buckets at `src/app/counselor/dashboard/page.tsx:36`–`:40` exclude it. No assignments UI caller found. Also assigning a different same-agency reviewer does not change primary counselor or grant visibility; `src/lib/cc/student-roster.ts:145` still denies that reviewer the student file. The session room is only a placeholder.
6. **Invite preassignment lacks same-agency membership validation.** Mint route forwards supplied `preassignedCounselorUserId` (`src/app/api/counselor/invite-codes/route.ts:62`) and helper inserts it (`src/lib/cc/invite-codes.ts:106`); redemption trusts it (`:170`). Unlike paid assignments, no same-agency membership check is present. A removed/foreign assignee can produce a link unusable by intended members; verify with isolated fixtures.
